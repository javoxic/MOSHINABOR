# Production readiness audit

- **Date:** 2026-11-09
- **Branch:** `audit/production-readiness`, based on `claude/jolly-mayer-wxbmkx` @ `3d1c974` (that branch is unchanged)
- **Scope:** the whole repository: backend, mobile, admin, shared packages, database, infrastructure, CI, docs and git history.
- **Method:** I read the code and wrote tests that probe for defects. Every defect below was reproduced by a failing test or a command before it was fixed. Where possible, I re-verified the fix the same way.

## Overall assessment

**Code: ready for staging and a controlled pilot.** No CRITICAL issues were found. All HIGH and MEDIUM issues found are fixed and verified. The full automated suite passes: 233 tests, plus all builds and Docker images.

**Public launch: BLOCKED BY EXTERNAL CREDENTIALS.** The following are not configured and cannot be verified here:

- **SMS:** Eskiz account and an approved OTP template. Without these, users cannot sign in.
- **Push:** EAS, FCM and APNs.
- **Release build and testing:** store signing, plus manual testing on real devices.

See [PRODUCTION_CHECKLIST.md](PRODUCTION_CHECKLIST.md) and [REMAINING_RISKS.md](REMAINING_RISKS.md).

### Areas audited with no defect found (now covered by added tests)

- **Maintenance engine**
  - Month, year and leap-day arithmetic.
  - The Asia/Tashkent midnight boundary (19:00 UTC).
  - Inclusive thresholds.
  - The stale-mileage boundary (30 vs 31 days).
  - "Whichever comes first", in both directions.
  - UPCOMING → DUE → OVERDUE progression, with overdue reminders repeating every 7 days.
  - The night send window.
  - Interval changes.
  - Paused schedules and restricted users.
  - Four parallel reminder-engine runs.
- **Authentication**
  - Parallel verification of one code authenticates exactly once.
  - Parallel code requests for one phone send exactly one SMS.
  - Parallel refreshes of one token yield exactly one new session.
  - Eskiz timeouts are retryable and never reported as success.
- **Authorization**
  - Every one of the 60+ non-public routes rejects anonymous requests.
  - Every one of the 30+ admin routes refuses an admin holding only `dashboard.view`.
  - 19 cross-user endpoint/method combinations return 404.
- **Account deletion:** request, cancel and purge, including stored file blobs. Other users are unaffected, and the phone can register again.
- **Schema:** `prisma migrate diff` shows no drift between the migrations and `schema.prisma`.

## Secret and history audit

- **Committed secrets:** none. History contains no `.env`, keys, certificates, `google-services.json` or provider credentials.
- **Test fixtures:** `backend/test/env-setup.ts` and `admin/playwright.config.ts` contain test-only secrets. They are used solely by tests and are now refused in production by L2.
- **`dump.rdb` in history:** it remains in the history of commits `cd6cc56`…`3d1c974` on both branches. Its content is non-sensitive test data (see M1), so **no credential rotation is required**. Optionally, purge it from history with [`git filter-repo`](https://github.com/newren/git-filter-repo):

  ```bash
  git clone --mirror git@github.com:javoxic/MOSHINABOR.git && cd MOSHINABOR.git
  git filter-repo --invert-paths --path dump.rdb --path-glob 'backend/storage-test/*'
  git push --force --mirror   # coordinate with collaborators first; rewrites all branches
  ```

- **Production secrets:** these come only from `infrastructure/deployment/.env` and Compose secrets. Both are gitignored, and their values are validated at startup.
