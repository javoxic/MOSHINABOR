# Remaining risks

These are open after the audit of 2026-11-09. None is CRITICAL.

## Deployment blockers: external credentials

| Item                                                                                                                  | Impact                                                         | Status                          |
| --------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- | ------------------------------- |
| Eskiz.uz account, sender ID and an **approved OTP template** that exactly matches `SMS_OTP_TEMPLATE_*`                | No user can sign in. The API returns `503 SMS_NOT_CONFIGURED`. | BLOCKED BY EXTERNAL CREDENTIALS |
| Expo/EAS project (`EAS_PROJECT_ID`), FCM V1 key with `google-services.json`, Apple Developer membership with APNs key | No push notifications. In-app notifications still work.        | BLOCKED BY EXTERNAL CREDENTIALS |
| Store signing (Android keystore, iOS certificates)                                                                    | No store binaries                                              | BLOCKED BY EXTERNAL CREDENTIALS |
| Domain, TLS edge proxy, production `.env`, backup passphrase                                                          | Cannot deploy                                                  | Operator task                   |

## Requires manual testing on real devices

- **HEIC photo upload from an iPhone:** the conversion code is unit-tested, but the device itself is not.
- **Push:** permission prompts on iOS and Android 13+, receipt and tap-to-open deep links, and token rotation after reinstalling the app.
- **Session restore** after the app is killed. Biometric/Keychain behavior after an OS update.
- **Offline mode** on a real network transition, airplane mode and a weak signal.
- **Layout:** small screens (≤ 360 dp), large font scaling, TalkBack and VoiceOver.
- **SMS delivery time and template text** on Uzbek operators (Beeline, Ucell, Mobiuz, Uzmobile).

## Accepted technical risks

| ID  | Risk                                                                                       | Severity              | Actual impact                                                                                                                                                                                                | Mitigation                                                                                                                                                   |
| --- | ------------------------------------------------------------------------------------------ | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| R1  | `image-size` < 2.0.3 (2 advisories, rated high) in `expo › @expo/metro › metro`            | Low in practice       | Only Metro's asset bundler uses it, at **build time**, to read the project's own icons and images. It is not shipped to devices or servers. A malicious image would have to be committed to this repository. | The patched 2.x line is API-incompatible with Metro: overriding it broke `expo export`, which I verified. Re-check when Expo updates Metro.                  |
| R2  | `deepmerge` 4.x (low) in `@expo/config`                                                    | Low                   | Build-time merging of trusted configuration files. No patched version has been published.                                                                                                                    | Monitor upstream.                                                                                                                                            |
| R3  | Push delivery is at-least-once                                                             | Low                   | If Expo accepts part of a batch and the job then fails, a BullMQ retry can deliver a duplicate push to some devices. In-app notifications are deduplicated by a database constraint.                         | Accepted. Duplicates need a mid-batch network failure.                                                                                                       |
| R4  | The Eskiz API token is cached in Redis                                                     | Low                   | Anyone with Redis access could send SMS until the token expires (30 days).                                                                                                                                   | Redis is password-protected and only reachable inside the internal Compose network. Rotate the Eskiz password if Redis is compromised.                       |
| R5  | The Redis password is visible in the container process list (`redis-server --requirepass`) | Low                   | Visible only to whoever has `docker` access on the host, who already controls everything.                                                                                                                    | Accepted. Alternative: a mounted `redis.conf`.                                                                                                               |
| R6  | The OTP per-IP limit was raised to 60 per hour for carrier NAT                             | Low                   | An attacker with a single IP can trigger more SMS.                                                                                                                                                           | Per-phone limits (5 per hour, 10 per day) and the cooldown still apply. Monitor SMS spend in the Eskiz cabinet. Configurable with `OTP_MAX_PER_IP_PER_HOUR`. |
| R7  | Local single-node file storage                                                             | Medium (availability) | Losing the disk loses uploads since the last backup.                                                                                                                                                         | Daily encrypted backups. Copy them off-host. Use shared storage before scaling to several hosts.                                                             |
| R8  | `dump.rdb` (test data only) remains in the history of older commits                        | Informational         | Contains no credentials or personal data.                                                                                                                                                                    | Optional history purge: PRODUCTION_AUDIT.md gives the steps.                                                                                                 |
| R9  | No independent penetration test                                                            | Medium                | Unknown issues.                                                                                                                                                                                              | Commission one before a public launch.                                                                                                                       |
| R10 | The API image is large (about 850 MB uncompressed, 199 MB compressed)                      | Low                   | Slower deploys.                                                                                                                                                                                              | It includes the Prisma CLI for migrations. It could be split into a separate migration image later.                                                          |
| R11 | No hosted error tracker (Sentry or similar)                                                | Medium (operability)  | Errors are visible only in the structured logs; `monitor.sh` alerts on bursts (more than `ERROR_THRESHOLD` per 5 min) but not on single rare errors.                                                         | Review logs daily during the pilot. Integrating a tracker needs an account and a DSN, which is an operator decision.                                         |
| R12 | Mobile release builds depend on a cache-free bundle                                        | Low (after fix)       | Metro's transform cache once carried the staging API URL into a production export. Fixed: the URL now comes from the build manifest, and the export scripts use `--clear`.                                   | EAS cloud builds start from a clean cache. Locally, always use `pnpm --filter mobile export` / `export:pilot`, never a bare `expo export`.                   |
| R13 | Staging and pilot run without real-device verification                                     | Medium                | Device-specific defects (permissions, Keychain, HEIC, push) are possible.                                                                                                                                    | Execute [PILOT_TEST_PLAN.md](PILOT_TEST_PLAN.md) on the device matrix before inviting testers.                                                               |
